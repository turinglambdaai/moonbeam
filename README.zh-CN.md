# Moonbeam

**agent 时代的自建远程接入——你的机器、你的中继、三桌面平台全支持。**

Moonbeam 让你——和你的 agent——从任何地方回到自己的机器：隧道上的远程终端、文件传输与按需的桌面画面，加上远程唤醒和自建信令/中继。服务器件部署在自己的 NAS 或任意云服务器上，回家的路不依赖任何一家的服务器。

## 为什么做

agent 时代改变了工作发生的位置：你的代码、你的任务、你的编码 agent，跑在"别处"的机器上——家里、公司、桌子底下那台主机。你需要的是立刻回到它们身边：一条烂网络里也活着的终端、不动声色就传完的文件、必要时看一眼的屏幕，以及人到了机器就醒来的开机。

网易 UU 远程这类消费级工具证明这种体验存在：装上、登录，你的电脑就在那里。但整份体验踩在你不拥有的基础设施上：

- **无法自托管。** 那些魔法——打洞、中继、唤醒信令——都在厂商的服务器上。这是一个你无法拥有的免费产品：规则与上限不可协商，哪个平台有客户端不由你决定，存续也不在你手里。

Moonbeam 把这份体验拿回来：一条跑在你自己硬件上的控制面。它刻意**不**重造视频管线——桌面画面复用成熟的开源串流生态（Apollo/Sunshine 主机端 + Moonlight 客户端，以独立进程驱动）。Moonbeam 拥有的是其余的全部，而其余的全部就是产品：隧道、终端车道、文件传输、唤醒、配对、编排。

打游戏不是设计目标。串流生态顺手就能给，Moonbeam 为办公与 agent 车道优化——文本优先，视频按需。

## 工作方式

三件套，一个目标：你的机器就在那里。

- **Host 管家** —— 常驻 macOS、Windows、Linux 的守护进程：隧道、终端会话、文件传输、按需唤醒，以及由 Apollo/Sunshine 驱动的按需桌面画面（替你装好配好；上游的平台成熟度有差异——如 Apollo 的虚拟显示器目前仅 Windows——如实陈述，绝不隐瞒）。
- **Client**（macOS、Windows、Linux）——局域网发现主机，驱动隧道，承载文本车道：远程终端（多会话、断线继承、TUI 友好）与文件传输，链路差到视频跑不动时依然可用。需要看屏幕时，以独立进程拉起 Moonlight 客户端。
- **Relay/信令服务器**（单二进制 + Docker）——信令协调、打洞辅助、带宽中继兜底、远程唤醒指令下发。部署在自己的 NAS（常在家的设备可以直接发魔法包）或任意云服务器。P2P 优先，中继只是兜底——而文本车道几乎不占用它：一个终端会话吃的是千比特，不是兆比特。

一切皆可脚本化优先——稳定的 CLI 与确定性输出——agent 用它和你用它一样顺手。

连接是一条梯子而不是赌运气：局域网与 IPv6 直连优先，其次 UDP 打洞，自建中继只做兜底——每一级都先试更便宜的路径，再花中继的带宽钱。

全平台路线遵循家族标准：桌面三平台先行，iOS/iPadOS/watchOS/Android 客户端等 Rivet 移动宿主就绪后必做。Moonbeam 主机端对桌面画面说标准 Moonlight 协议，凡存在直连路径（局域网、IPv6、端口转发）官方 Moonlight 移动客户端即可使用；过渡的桥是中继上的 WireGuard 端点（M3），官方客户端经它直连。

## 路线图

- **M0** —— relay 服务器最小版（信令 + 远程唤醒）、Host 守护进程与 Client CLI，文本车道在局域网端到端验证：终端 + 文件传输。暂不涉及视频栈。
- **M1** —— 外网链路：打洞优先、中继兜底，文本车道人在天涯也能用。"人在天涯也能连上家里"的一刻。
- **M2** —— 桌面画面：Host CLI 一键装配 Apollo/Sunshine，Client 以独立进程驱动 Moonlight——办公级调优，不做电竞级打磨。GUI 壳（macOS / Windows / Linux）与自动化配对。
- **M3** —— 完整唤醒体验（NAS 容器 + 云入口）、会话监控、被控端防窥、经 Apollo 按客户端虚拟显示器实现的无线副屏，以及中继上的 WireGuard 端点——给官方移动客户端当桥。
- **M4** —— 家族打包标杆（dmg / msi / deb / rpm / AppImage、更新 feed）与产品主页。
- **M5+** —— 移动端与手表客户端，等 Rivet 移动宿主；视情况在 GPLv3 义务下与主机端深度整合（fork Apollo）。
